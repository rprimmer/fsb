\section{The Guard}
\label{sec:guard}

\subsection{Opening a path}

Every operation begins by opening the path, in this order.  The order is the design.

\begin{enumerate}
  \item \textbf{Canonicalize.}  The path must be non-empty, contain no NUL, and be
        absolute.  It is cleaned lexically (\code{.}, \code{..} and repeated slashes
        removed) and reduced to one spelling of each alias (Section~\ref{sec:aliases}).
        URL-decoding has already happened, exactly once, in the HTTP layer; the guard
        never decodes, so a literal \code{\%2e\%2e} is just a name.
  \item \textbf{Lexical deny check.}  The cleaned path is matched against the deny
        rules \emph{before the file system is touched}.  The type of the final
        component is not yet known, so it is treated as a file here; a rule that
        applies only to folders is decided in step~7.  (Assuming a folder would refuse
        a plain file that shares its name with a \code{dir/} rule although listings
        show it.)
  \item \textbf{Open without blocking.}  The path is opened read-only and
        non-blocking, so that a pipe or a device cannot hang the server.  A permission
        error is examined (Section~\ref{sec:ancestor}) before it is reported.
  \item \textbf{Reject special files.}  On the descriptor, anything but a regular file
        or a folder is refused.  Only then is blocking restored.  Some special files
        never reach a descriptor to reject this way: opening a UNIX domain socket's
        path fails at the syscall itself (\code{EOPNOTSUPP} on macOS, historically
        \code{ENXIO} on Linux), so those two errnos are mapped to the same refusal as
        every other special file, rather than left to fall through as an unrecognized
        error (Finding~17).
  \item \textbf{Resolve and confirm.}  The real path is resolved (symbolic links
        followed), and the guard confirms that the file at that real path is the
        \emph{same file} as the open descriptor (device and inode).  If not, the path
        changed between the two steps and the request is refused as a race.
  \item \textbf{Roots and deny on the real location.}  The real path must lie inside a
        root (by identity, Section~\ref{sec:roots}), and must not match a deny rule.
  \item \textbf{Precise lexical check.}  With the type now known, the requested path is
        matched again.  A path is thus refused if \emph{either} its spelling or its real
        location is denied.
  \item \textbf{Other names.}  A regular file with several names is checked against
        the hard-link index (Section~\ref{sec:linkindex}).
\end{enumerate}

Everything that later reads bytes does so through the descriptor this returns, so
the decision and the read concern the same file.  Extended attributes, for example,
are read from that descriptor.

\subsection{Aliases}
\label{sec:aliases}

macOS keeps its user data on a separate volume whose folders appear at ordinary
paths through \emph{firmlinks}: \code{/Users} and \code{/System/Volumes/Data/Users}
are one directory.  Firmlinks are not symbolic links, so resolving links does not
reduce them, and a rule for \code{/Users/me/.ssh} would not match the longer
spelling.  Every path is therefore reduced to its ordinary form before any comparison
with a root or a rule.

The reduction compares path components one at a time, with the same name equality as
the rules (Section~\ref{sec:fold}), and rebuilds the path from the firmlink's own
spelling.  An earlier version sliced the path to the byte length of the prefix, which
cut a folded spelling (\code{/S}\emph{long-s}\code{ystem}) in the middle of a
character and left it unreduced.  The firmlink table is read from
\code{/usr/share/firmlinks}, with a built-in copy as fallback.

\subsection{Roots}
\label{sec:roots}

Each root is resolved to its real path at startup, and its identity (the file
information of the folder) is kept.  Whether a path lies inside a root is then decided
by taking the leading components of the path that correspond to the root and
comparing the \emph{identity} of that folder with the root's.  Comparing folded text
would be right on a case-insensitive volume but would admit a different sibling on a
case-sensitive one (\code{Public} for a root of \code{public}).  This is an allow
decision, so it must not over-match.

\subsection{Permission errors inside denied places}
\label{sec:ancestor}

An unreadable file inside a denied folder must look exactly like a missing one, or its
existence leaks.  When opening fails with a permission error, the guard resolves the
longest prefix of the path that can be resolved (an unsearchable folder stops the
resolution of what is inside it, not of the folder itself), rebuilds the full real
path from it, and applies the deny rules to that.  Only if nothing denies it is the
permission error reported.

\subsection{Listing}

A listing opens the folder as above and receives its real location.  Each child is
then judged by \emph{that} location and not by the symbolic link or alias the folder
was reached through, in one function used by both listing and search
(\code{entry}), so that search cannot show what listing would not.  For a child:

\begin{itemize}
  \item a symbolic link is resolved; a broken one is marked; one whose target is denied
        or outside the roots is omitted; the target's size, date and type are shown;
  \item the child's path is matched against the deny rules and, separately, the hide
        rules, each ignoring the ancestors above the folder itself (so entering a hidden
        folder on purpose shows its contents);
  \item a regular file with several names is checked against the hard-link index.
\end{itemize}

Entries are handed out in batches as the directory is read, which is what lets the
interface paint before a huge folder has been read.

\subsection{Search}

Search is a breadth-first walk, so shallow matches come first.  Every folder is opened
through the same operation, every child goes through \code{entry}, denied and hidden
folders are never entered, and symbolic links to folders are never followed (which
also rules out cycles).  It stops at a result limit or an entry limit and reports that a limit
stopped it.  Names are compared after the folding of Section~\ref{sec:fold}, or, for
\emph{Match case}, after normalization only.

Three details keep the walk honest.  The entry limit counts every entry
\emph{examined}, including those a rule then rejects, because it bounds work; the
count reported back is of visible entries only, so it says nothing about how many were
excluded.  Folders are queued by path, so before one is entered its real location, as
the guard's own open reports it, is compared with the name it was queued under; if a
symbolic link has taken its place (or one above it) in the meantime, the children would
be judged under a name that is not where they are, so it is not entered (a test swaps a
queued folder for a link after the walk has queued it).  Finally, the search returns a
summary beside its results: a folder that is there and allowed but could not be opened,
one that failed partway through being read, and one skipped as just described count as
not searched, and the done line of the stream carries \code{incomplete} so the
interface says so.  A folder that is denied or has vanished is not counted: a denied
folder must look exactly like a missing one, and neither is a loss.  Cloud-only folders
are skipped by design and do not count either, so completeness means completeness of
the searchable, allowed content.

\subsection{Cloud-only files}

On macOS a file that exists only in the cloud carries a flag in its file information.
The guard checks it before any read and reports the file as not downloaded; the head,
the metadata, the previews and the archive listing all refuse to read it.  Reading such
a file would make the system download it, which \texttt{fsb} must never do implicitly.
An explicit download by the user is the one path that reads it.  The hard-link index walk
(Section~\ref{sec:linkindex}) and the copy of a package for Quick Look do not enter a
cloud-only folder either: the walk skips it (its contents are not on this disk, so they
hold no other name of a file that is), and a package with a cloud-only part is refused.

A \emph{folder} can carry the same flag: the newer File Provider domains (iCloud Drive,
OneDrive and similar) can make a whole folder a placeholder, not only the files inside
it, and reading its contents is exactly as capable of triggering a download as reading a
dataless file's bytes is.  Listing and search each check the flag on a directory before
opening it for reading, refusing it the same way as a dataless file, rather than only on
the files this directory would contain.  This was missing for a released cycle: nothing
had ever put a real File Provider placeholder folder in front of the guard, only a
synthetic flag on individual files, so listing one fell through to the directory read and
surfaced whatever the provider's virtual file system returned for it, unrecognized, as an
internal error (Finding~19).

\subsection{Other files and endpoints}

\begin{description}
  \item[Head] reads at most a stated number of bytes from the descriptor, and returns
        text only if it is valid UTF-8 without control characters; binary contents never
        leave the guard.
  \item[Metadata] describes the entry, and reads extended attributes through the
        descriptor, capped in number and size.
  \item[Sniffed endpoints] (image, PDF, archive) share one routine that opens the file,
        reads its first bytes, decides the kind from them, and rewinds; they differ only
        in the test applied (Section~\ref{sec:content}).
  \item[Quick Look copy] (\code{CopyForQuickLook}) opens the document as above and copies
        bytes from the verified descriptor into a private folder; in a package it opens every
        part through the guard by full path, so each part is judged exactly as a direct
        request for it would be (Section~\ref{sec:quicklook}).  It writes only into the
        temporary folder it is given, never into the roots.
\end{description}

\subsection{Hard links}
\label{sec:linkindex}

Rules name paths, and a hard link is another name for the same file, so a hard link to a
denied file is invisible to them.  The guard therefore judges a regular file with more
than one name by its identity: if any of its names is denied, all of them are.

\paragraph{The index.}  Finding the other names of a file means visiting every file
under the roots, because the operating system offers no way to ask.  A walk therefore
builds an index from identity (device and inode) to what it saw of the file: its names
as real paths, the link count it saw, and whether any name is denied.  It contains only
regular files with more than one name (a few dozen on a typical home folder).  The walk
also covers the \emph{protected locations} named by the program at startup (the
credential folders of every home), so that a link from a served folder to a credential
file outside the roots is found.  A name is identified by the folder holding it (by
identity) and its last component folded as the file system compares names
(Section~\ref{sec:fold}); two paths that spell one name (a firmlink, a folder walked
twice, \code{a.txt} and \code{A.TXT}) therefore count once.  On a case-sensitive volume
two names that differ only in case also count once, which undercounts and so refuses:
the safe direction.

\paragraph{The walk is in the background.}  On a home folder of 700{,}000 files it takes
about 18 seconds, which must not be spent inside a request.  It is started at startup,
and nothing is served as a multi-name file until it has finished.  Walks are spaced by at
least twice the time the last one took (and never closer than a fixed cooldown), and are
bounded by an entry count and a time.  A cloud-only folder is not entered.

\paragraph{The policy: verify all the names.}  A file with several names is served only
when the index accounts for every one of them, now.  The decision
(\code{judgeLinked}) requires that the walk found as many distinct names as the file has
links, that none is denied, and that each recorded name is still a real path to this very
file when it is used: it is looked at again, resolved, and must still reach the same
identity with no symbolic link along it.  Nothing about the file itself is trusted to
reveal a change, because renaming or moving a folder renames the files in it without
touching them (an earlier design that trusted a file whose change time was old enough
was broken exactly this way by a second review, and was replaced).  Anything else is
refused, never guessed: the index is not ready, a name lies where the walk does not look
(a pnpm store outside the roots) or in a folder it could not read, the walk stopped at its
limits, or the names changed.  This was once the other way round for a file the walk
could not see (it was allowed after a second walk failed to find it); a review showed
that fail-open policy let a hard link to a denied file through, and the decision is now
fail closed throughout.

\paragraph{Retry.}  A pair made while a walk runs can be recorded with one name, and one
more walk settles it.  That walk is owed once per file and link count, and is spent only
when it really starts: a first look during the cooldown, or while another walk is
running, refuses the file without using it up (an earlier version marked it spent
before checking, so the file stayed refused after the cooldown).  If the extra walk still
finds fewer names than links, the file is refused without walking again until something
changes.

\paragraph{Listings and searches reuse a verdict for one second.}  A folder holding many
names of one file would cost one check per name, each a look at every recorded name, so a
listing or a search remembers the verdict for a file (keyed by identity and link count,
so a name added meanwhile is noticed) --- but only for a short, stated time.  After one
second (\code{linkMemoTTL}) the names are checked again, because a rename that leaves the
count unchanged, one of two names moved onto a denied name, would otherwise stay
invisible for as long as a slow consumer or a long search ran.  This is a memo reuse
interval, not a guarantee that every row on the screen reflects the file system
now: entries already sent are not retracted, and the check made when a file is
\emph{opened} never uses the memo.  The remaining staleness affects a name or a size
shown, not access to contents.

\paragraph{What is not covered.}  A denied name that lies outside every root and every
protected location is not found; the file is then refused while the file has links the
walk cannot account for, rather than served.

# Security

fsb serves your own files to your own browser, so its job is to make sure that
*only* your browser session can reach them, that it never writes, and that the
secrets you have excluded stay excluded.

## Threat model

**Defended against**

- **A malicious web page in your browser** trying to read your files through fsb (cross-site requests, DNS rebinding, framing, cross-origin image or script loads).
- **Another user or process on the machine** connecting to the port: it has no launch token and no session cookie. On Linux it cannot use either even if it obtains it (see *Launch URL in a command line* below).
- **A path that names a denied file in a different way**: `..` traversal, symlinks (including symlinks to directories that contain denied entries), case variants, Unicode variants, macOS firmlink aliases (`/System/Volumes/Data/...`), a symlinked home directory, awkward file names (trailing whitespace, newlines).
- **Untrusted file content**: nothing from a file is rendered as HTML; inline responses are limited to sniffed PNG/JPEG/GIF/WebP served in a sandbox (plus PDFs in the browser's own viewer, and PNG pictures that fsb has macOS Quick Look draw of iWork and Office documents); a cloud-only file is never read by hover, preview or metadata.

**Not defended against**

- **Anything already running as you.** Malware with your privileges can read the same files without fsb. fsb is not a sandbox.
- **Someone with your unlocked machine, or root.**
- **Secrets that are not covered by a deny rule.** fsb can only hide what its rules name; see `~/.config/fsb/deny`.

## What is guaranteed, and how

| Guarantee | Enforced by |
|---|---|
| Reachable only on `127.0.0.1` by your session | Fixed loopback bind; exact `Host` allowlist; strict `Origin`/`Referer`/`Sec-Fetch-Site` checks; a single-use launch token, at a URL that does not name the prefix, exchanged for an `HttpOnly`, `SameSite=Strict` cookie whose `Path` is a random per-launch prefix under which everything is served (browsers cannot scope a cookie by port, so this is what keeps it from other local servers, which do not know the prefix); `Cross-Origin-Resource-Policy`, `X-Frame-Options` and CSP headers; on Linux, the launch token and the session cookie are accepted only on a connection of fsb's own user (`internal/connowner`), and a refused launch does not use the token up |
| Read-only | Only `GET`/`HEAD` are served, and there is no operation that changes what is served; the only files `fsb` writes are its own: in `~/.config/fsb/`, the rule files `--init` creates (never overwriting one), the last port used, and the PID and log of a `--background` instance (each opened without following a symbolic link or blocking, and written only if it is an ordinary file with a single name owned by the user, so nothing planted there can redirect a write or hang fsb); and, for a Quick Look picture, a copy of the document (made from a descriptor the guard opened) in a fresh private temporary folder (`fsb-quicklook-*`, mode 0700), removed when the picture is drawn or the request is abandoned |
| Deny rules block every access | One chokepoint (`internal/guard`) used by list, download, preview, head, metadata and search; rules are matched against the *real* location, after symlinks and aliases are resolved, and again on the file descriptor that was actually opened |
| A denied path looks like a missing one | Identical 404 status and body, including for unreadable files inside denied folders |
| Rendering a Markdown file cannot run code, load anything remote or reach the app | Three layers, each assuming the one before failed: raw HTML is escaped and links carry no `href` (`web/src/lib/markdown.ts`); the result is sanitized with DOMPurify; and it is shown in an iframe with `sandbox="allow-scripts"` (an opaque origin, so no session and no API access) whose own policy is `default-src 'none'` with only its one fixed script and style admitted by hash, and images limited to `data:`. Local images are fetched through the guarded preview endpoint, and remote images are replaced by a placeholder, so opening a file makes no outside request |
| A PDF preview is served only for real PDFs and cannot be framed by other sites | `/api/pdf` requires the `%PDF-` signature (never the name), is subject to the same guard and deny rules, refuses cloud-only files, and is sent with `nosniff`, `X-Frame-Options: SAMEORIGIN` and `frame-ancestors 'self'`. A CSP `sandbox` is not used here because browsers then refuse to display PDFs; rendering is left to the browser's own viewer |
| Listing an archive cannot extract, write or exhaust memory | `/api/archive` returns names and sizes only, never member data, through the same guard and deny rules. Format is decided from bytes; a zip's central directory is read record by record by fsb's own reader (not `archive/zip`, which holds all of it in memory), keeping only the first 1,000 entries, and stops after 200,000 entries or 64 MiB of directory, whatever the archive claims; a count that disagrees with the directory is refused; tar scanning stops after 200,000 entries or 512 MiB of decompressed stream; listing stopped at a limit is marked incomplete; member names longer than 4,096 bytes are cut (and an ellipsis added) for display; the 64 MiB directory budget is checked between records, so the last record may cross it by its own length; member names are shown as text with control characters replaced |
| A Quick Look preview never lets macOS read anything fsb would not serve | `/api/quicklook` is the one place fsb runs another program on a file: Apple's `qlmanage`, on macOS only (elsewhere nothing is copied or run), with a path as a single argument (no shell). It is never given the user's own path. `guard.CopyForQuickLook` opens the document through the guard (roots, deny rules, hard links to denied files, an iWork or Office extension, not cloud-only) and copies its bytes, from that verified descriptor, into a fresh private temporary folder; Quick Look draws the copy. A copy has no extended attributes or resource fork, so a Finder alias named like a document has nothing left to follow, and nothing can be swapped between the check and the drawing. In a package document (a folder), every file is opened through the guard by its full path and must still lie inside the package; a part that is denied, a link, a hard link to a denied file or not a regular file is left out of the copy, as a listing leaves it out, so the answer does not reveal it; a cloud-only part is refused (409). A copy is limited to 256 MB and 5,000 entries. The output must be a single PNG under 20 MB and is served with `sandbox; default-src 'none'`, `nosniff` and `no-store`. Copying and drawing run at most two at a time. Copying stops after 20 seconds, and `qlmanage` after 5 (it never finishes on a document it cannot draw); cancellation is requested as soon as the request is abandoned and takes effect at the check points (between reads, between members; `qlmanage` is killed at once), and the temporary folder is removed. The 20 seconds is cooperative: it is checked between reads and once more when a read returns, so work that ran out of time fails instead of succeeding, but a read that the file system itself is holding up (a stalled network volume) cannot be interrupted and keeps one of the two slots until it returns. Archive listings are canceled the same way, at the same kind of check points. Keynote documents (`.key`) stay denied by the core `*.key` rule |
| Only the configured roots are reachable | Real-path check against the roots; symlinks that leave them are refused |

The behavior is specified in [functional/](functional/) (sections on rules and security behavior) and the construction in [design/](design/); the laws are in [algebra/](algebra/).

## Known limitations

- **Launch URL in a command line.** When fsb opens the browser, the single-use launch URL is an argument of the program it runs: `xdg-open` or the `--browser` program on Linux, and the browser that starts, until the browser first uses it; `open` on macOS, briefly. Another user on the same machine can read other users' command lines (Linux `/proc/PID/cmdline` unless `/proc` is mounted with `hidepid=2`; `ps` on macOS). The URL does not name the path prefix, so it does not tell them where the session cookie will be sent: a server of theirs on another port cannot ask your browser for it (an independent review showed that, while the URL named the prefix, a page of theirs that your browser visited once could capture the cookie). On Linux the URL also gives them nothing by itself: fsb accepts the launch token, and the session cookie, only on a connection whose client end belongs to fsb's own user (looked up in `/proc/net/tcp`, once per connection), and a refused launch leaves the token unused, so your browser still gets in; fsb warns about the first few refusals. Two consequences: a connection that arrives through a port forward or proxy counts as the forwarder's user, so a forward *you* run (`ssh -L`, `socat`, Colima) lets anyone who can reach its other end through; and where the owner cannot be determined (no `/proc`, a user namespace that hides other users, WSL or gVisor, where the table may be empty or the browser's connection comes from a relay), the launch URL is refused, so fsb cannot be used there. A used token is refused without a lookup or a warning. On macOS, which offers no such lookup, the URL is visible only while `open` runs, a fraction of a second; on a shared Mac, start fsb with `--no-open` and paste the printed URL.
- **Hard links.** Rules are path-based, so a file with several names is judged by identity: if any of its names is denied (a `.env` or `.pem` anywhere in the roots, or anything in a credential folder of any home), all of them are refused and unlisted. The names come from an index of multi-name files under the roots and credential folders, built in the background at startup (about 20 seconds for a 700,000-file home) and refreshed, at least 15 seconds (or twice the last walk) apart, when a file cannot be accounted for. A file is served only when the index accounts for all of its names, now: the walk found as many distinct names (counted by folder identity and name, so a folder reached twice counts once) as the file has links, no deny rule matches any of them, and on each use every recorded name is still a real path (no symbolic link along it) to the same file (for a listing or search, the verdict is reused for at most one second, so a name or size shown can lag a rename by that long; opening a file never reuses it). Nothing about the file is trusted to reveal a change, since renaming or moving a folder renames the files in it without touching them. So a file with a name outside every root and credential folder, in a folder fsb cannot read (permissions, macOS privacy protection), or beyond the walk's limits (20 million entries, 10 minutes) is refused, not served; so is one whose names changed since the walk, until the next. Remaining exposure: the moment between this check and the file being opened.
- **Broad patterns have costs.** `*.key` also matches Keynote files, `.env` also matches a folder called `.env`, and `.env.*` also matches `.env.example`. You can remove a pattern from your deny file; fsb then warns at startup and in the UI.
- **`--root /` widens what is exposed.** Deny rules still apply, but only to what they name. On Linux, device files are never opened, and a process's environment and command line in `/proc` (where API keys often are) show as empty: the system reports them as empty files and fsb never reads or sends more than a file's size (a test pins this down).
- **Explicit downloads of cloud-only files.** Downloading a file (right-click its name and choose the browser's download item) that is an iCloud file not stored locally starts the download. Hover, preview and metadata never do, and no walk enters a cloud-only folder: not listing, search, the background hard-link index (whose coverage is unaffected, since such a folder's contents are not on the disk), nor a Quick Look package copy (which refuses the package).
- **Quick Look parses the document.** The picture of an iWork or Office document is drawn by macOS's own Quick Look generators from fsb's private copy. A document crafted to exploit a flaw in one of them is outside what fsb can defend against (macOS runs them in its own sandboxed service, as it does when Finder shows the same picture).
- **`--stop` recognizes fsb by its executable file and owner.** A process of yours whose executable file is itself named `fsb` would be taken for fsb; another user's processes, and programs that merely call themselves `fsb`, are not.
- **Rules are read at startup.** Restart to apply changes.
- **Response timing is not equalized.** A denied path can answer slightly faster than a missing one; the status and body are identical.

## How it is tested

- **Unit and integration tests** for the rule matcher, the guard, the HTTP layer and the API, including deliberately hostile paths.
- **Fuzzing** of the path guard, the rule matcher, the HTTP middleware and the whole server stack. The guard fuzzer uses an oracle that does not trust fsb's own rules: whatever it returns must not be the same inode as a known secret or contain a secret marker. A fuzzer only reaches what its test fixture contains, and an early version missed a bug for that reason; keep the fixture broad.
- **Real-browser tests** in Chrome and Safari, including attacks from a second origin and a DNS-rebinding hostname. See [e2e/README.md](../e2e/README.md).
- **Linux distributions** (October 2026): a smoke test on Debian, Ubuntu, Fedora, Alpine and Arch in Docker (`make linux`). It found that the core deny rules named only the macOS locations of browser data, so on Linux the Chrome, Chromium, Firefox, Brave and Edge profiles (including Flatpak installs), the GNOME and KDE keyrings and the `pass` store were served; fixed in 1.0.2 and 1.0.4. An independent review of that work then found more it had missed, Snap Chromium and Firefox 147's new profile location among them; fixed in 1.0.6, with Vivaldi, Opera, Thunderbird and the NSS key store. With `/` as a root on Linux, `/proc`, `/sys` and `/dev` were probed through every endpoint and nothing leaked.
- **Mutation checks**: removing a deny rule (or reverting a fix) must make these tests fail.
- **An independent review** by a reviewer with no access to the author's reasoning or tests. It found real problems, all fixed and covered by regression tests: listings and search through a symlinked directory leaked denied names; a newline or trailing space in a file name defeated some rules; an unreadable file inside a denied folder answered 403 instead of 404. Earlier, a macOS firmlink alias was found to bypass deny rules under `--root /`. While writing the algebraic specification (see [`algebra/`](algebra/)), a further bypass was found: APFS compares names with *full* Unicode case folding, so `~/.ßh` opens `~/.ssh` (also `ſ`, the Kelvin sign and ligatures such as `ﬁ`), which the rule matcher's simple folding did not treat as the same name. Rules are now compared after the same folding as APFS, verified against this file system. A rule file could also load without error and do nothing (a byte order mark, old-Mac line endings, an inline comment, `~user/`, quotes, invisible or slash-lookalike characters); the first two are now handled and the rest stop fsb from starting with a message that says what is wrong. A follow-up audit of every name comparison found two more: the firmlink prefix (`/System/Volumes/Data`) was matched by byte length, so an aliased spelling dodged reduction under `--root /`; and root containment compared spellings, which on a case-sensitive volume admitted a sibling folder differing only in case. Containment is now decided by file identity. A differential test (`guard/differential_test.go`) then had the operating system itself decide which of thousands of generated spellings of each secret really reach it (case, folding aliases, decomposed accents, separators, dot segments, firmlink and symlink aliases, named forks); every one is refused, and the test fails about 1,500 times if the folding fix is reverted. The same audit found that the credential folders were only protected under the current `$HOME`; they are now matched at any depth, so a Time Machine copy or a clone of the home folder, another account's home, or a wrong `$HOME` do not expose them.
- **A second independent review** (October 2026), of Quick Look, background mode and process control, found that a Finder alias named like an Office document made Quick Look draw the alias's target, which could be denied or outside the roots (confirmed by drawing a file from a denied folder). Quick Look now draws a private copy that fsb read through the guard, and a regression test makes a real alias with the system's own API and checks that its target is never drawn. It also found: that a denied file inside a package changed the answer (now left out silently, as listings do); that `--stop` trusted the name a process gives itself (now its executable file, owner and recorded start time); and that fsb's own files in `~/.config/fsb` were written through symbolic links (now refused). Each has a regression test that fails if the fix is reverted.
- **A third round of independent review** (October 2026), after external review comments (eleven findings) and the fixes they led to. The external review's findings, all confirmed and fixed, included: an unseen multi-name file was allowed during the index's rebuild cooldown; the index trusted names recorded at the last walk; a zip's entry limit could never trip (a 16-bit count against 200,000) and the standard library built the whole directory first; the index walk and the Quick Look package copy entered cloud-only folders; a symbolic link to `/` passed the root check; an image fetch read its whole body before checking its size. A review of those fixes found two further hard-link bypasses, and a second found defects in the fixes: a verdict remembered for a whole response hid a rename that kept the link count, a search could enter a folder swapped for a symbolic link after it was queued, a retry walk was spent by a lookup that could not start it, plain tar listing lost its seek and read every member, a copy that expired during a read could report success, a folder that could not be opened left a search looking complete, and an empty extended attribute that grew between two system calls caused a panic. Each has a regression test that fails without its fix. The last review found nothing further. What remains is stated above as limits: a one-second reuse of a verdict, cooperative cancellation, and cloud-only folders left out of search.
- **Dependency scanning**: `govulncheck` and `npm audit`, in CI on every push.

None of this is a guarantee. It is a record of what has been checked. Before wider distribution, a further independent review is recommended.

## Reporting a vulnerability

fsb is provided as-is and is not actively maintained, so there is no private reporting channel and no promise of a fix. If you find a vulnerability, consider it a reason not to use fsb for the affected purpose. If you open an issue, please describe the problem without a working exploit.

\section{Invocation and Configuration}
\label{sec:invocation}

\subsection{Command line}

\begin{req}{CLI-1}
The command is \code{fsb [flags] [path]}.  With no flags and no path it serves the
user's home folder.
\end{req}

\begin{req}{CLI-2}
The optional \code{path} names the first root.  More than one path argument is an
error.  A path that does not exist, or is not a folder, is an error.  Symbolic links
in a root are resolved, so a root is always a real location.
\end{req}

\begin{req}{CLI-3}
\code{--root PATH}, which may be repeated, adds further roots (for example
\code{/Volumes/Data}).  All roots are equal: each is listed as a place the user can
switch to when there are several.  A folder given more than once, under any
spelling (a trailing slash, a symbolic link, \code{--root \~{}} when the home folder
is already the default root), is served once.
\end{req}

\begin{req}{CLI-4}
The folder \code{/} is refused as a root unless \code{--allow-system-root} is given;
the message says so.  The decision is made on the folder itself, after symbolic links
are resolved, not on how it was spelled: a path argument, a \code{--root} or a home
folder that is a symbolic link to \code{/} is refused too.  Rules
(Section~\ref{sec:rules}) apply to a root of \code{/} as to any other root.  On
Linux, \code{/proc}, \code{/sys} and \code{/dev} can then be listed, but device files
are never opened (\rid{SEC-14}), a path through a process's \code{root}, \code{cwd} or
\code{fd} entries in \code{/proc} is judged by the file it reaches, and a process's
environment and command line show as empty: the system reports them as empty files,
and nothing past a file's size is read or sent.
\end{req}

\begin{req}{CLI-5}
By default the launch URL is opened in the user's default browser.  \code{--no-open}
only prints it.  \code{--browser NAME} opens it in a browser of the user's choosing
instead: on macOS the named application (for example \code{"Google Chrome"}), on
Linux the named program, run with the URL as its one argument (for example
\code{firefox}; it takes no arguments of its own).  A name that begins with \code{-}
or contains a NUL, carriage return or newline is refused before anything starts.
On Linux the default browser is opened with \code{xdg-open}, and only when there is
a display (\code{DISPLAY} or \code{WAYLAND\_DISPLAY}): without one, as over
\code{ssh}, \code{xdg-open} could start a text browser that would use the
single-use URL itself, so the URL is only printed; \code{--browser} is run
regardless.  The program \texttt{fsb} runs to open the browser on Linux runs in a
session of its own (Control-C in the terminal stops \texttt{fsb}, not the browser),
with no terminal input or output, and inherits nothing of \texttt{fsb}'s
background handoff (\rid{CLI-17}); one still running after 3 seconds, as a browser
it started may be, counts as having opened it.  \texttt{fsb} serves before it opens
the browser.  If the browser cannot be opened, \texttt{fsb} says so, with a hint
that names \code{--browser} only when it was given and, on Linux, \code{xdg-utils}
when \code{xdg-open} is missing; it keeps running, and the printed URL remains
usable.  On systems other than macOS and Linux the URL is only printed.
\end{req}

\begin{req}{CLI-6}
\code{--debug} enables verbose logging on standard error and makes a request for a
denied path answer with a body that names the matching rule (status still 404).  No
other flag or setting reveals which rule matched.
\end{req}

\begin{req}{CLI-7}
\code{--init} writes the default rule files (Section~\ref{sec:config}) and exits.  It
creates the folder \code{\~{}/.config/fsb} with mode \code{0700} if needed, creates each
file with mode \code{0600}, and \emph{never overwrites} a file that exists: it reports
that the file was left unchanged.  The rule files are the only files \texttt{fsb}
creates that the user is meant to edit; its other files are listed in \rid{CFG-5}
and \rid{CFG-6}.
\end{req}

\begin{req}{CLI-8}
\code{-h} or \code{--help} prints the usage text and exits with status 0.  An
unknown flag prints the error and the usage text and exits with status 1.
\end{req}

\subsection{Startup output}

\begin{req}{CLI-9}
On success \texttt{fsb} prints, on standard output, one line naming the roots it
serves and the loopback address and port, one line giving the launch URL, and one
line saying how it is stopped (Control-C, or \code{--background}; under
\code{--background} the line instead names its process and \code{fsb --stop}).
The port is the one remembered from the last successful start (\rid{CFG-5}), or one
chosen by the operating system when nothing is remembered; \code{--port}
(\rid{CLI-15}) overrides it for one run.
\end{req}

\begin{req}{CLI-10}
The launch URL has the form \code{http://127.0.0.1:PORT/PREFIX/?token=TOKEN}, where
\code{PREFIX} and \code{TOKEN} are random values generated at each start
(Section~\ref{sec:security}).  It works once; opening it a second time is refused.
\end{req}

\begin{req}{CLI-11}
If one or more core deny rules are not in effect (\rid{RUL-16}),
\texttt{fsb} prints a warning on standard error at startup naming the paths that are
therefore browsable.
\end{req}

\subsection{Running and stopping}

\begin{req}{CLI-12}
\texttt{fsb} runs in the foreground (or, with \code{--background}, detached:
\rid{CLI-17}) until it receives \code{SIGINT} (Control-C) or \code{SIGTERM}
(as \code{fsb --stop} sends: \rid{CLI-18}).  It then stops accepting requests, allows requests in progress up to
three seconds to finish, and exits with status 0.
\end{req}

\begin{req}{CLI-13}
The exit status is 0 after \code{--help}, \code{--init}, \code{--show-deny},
\code{--show-ignore}, \code{--status} (whether or not \texttt{fsb} is running), a
successful \code{--background} start or \code{--stop}, and a normal shutdown, and 1
after any error, including \code{--stop} when no \texttt{fsb} is running.  An error is reported on standard error as one line beginning
\code{fsb:}, and no server is started.
\end{req}

\begin{req}{CLI-14}
\texttt{fsb} refuses to start, with a message that names the file and the line, if
the deny file or the ignore file cannot be parsed
(Section~\ref{sec:rulefiles}).  It never starts with weaker rules than the user wrote.
\end{req}

\begin{req}{CLI-15}
\code{--port N} uses exactly port \code{N} on \code{127.0.0.1} for this run
(\code{0} lets the operating system choose).  A value outside 0--65535 is refused
before anything starts.  The port given is not remembered (\rid{CFG-5}), so a one-off
choice never replaces the usual port.
\end{req}

\begin{req}{CLI-16}
\code{--show-deny} and \code{--show-ignore} print the deny or ignore rules that
would be in effect, one per line, and exit without serving.  A first comment line
names their source: the rule file, or the built-in rules when there is no file.  For
deny rules a last comment line names any core rule the file leaves out
(\rid{CLI-11}).  Given together, both lists are printed, deny first.  A rule file
that cannot be parsed is an error, as in \rid{CLI-14}.
\end{req}

\begin{req}{CLI-17}
\code{--background} starts \texttt{fsb} detached from the terminal (in a new
session, so closing the terminal or pressing Control-C there does not stop it),
prints the startup output of \rid{CLI-9}, and returns to the shell once it is
serving and has opened the browser (\rid{CLI-5}); the line naming its process is
printed only then.  If startup fails, or the instance is stopped before that point
(Control-C does not reach it, but \code{fsb --stop} does), the error is reported as
in \rid{CLI-13}, the start counts as failed, and nothing is left running.  If an \texttt{fsb} is already running (as found by \rid{CLI-18}), the
start is refused with a message naming it.  Output after startup (such as
\code{--debug} logging) goes to the log file of \rid{CFG-6}.
\end{req}

\begin{req}{CLI-18}
\code{--stop} stops the running \texttt{fsb}: the one started with
\code{--background} (from its process-number file, \rid{CFG-6}), or else an
\texttt{fsb} started any other way that is listening on the port remembered in
\rid{CFG-5}.  It sends \code{SIGTERM}, waits up to five seconds for the process to
exit, and reports it.  Only a process that is \texttt{fsb} is ever signaled: it must
belong to the same user and have been started from an executable file named
\texttt{fsb} (the name a process gives itself does not count; a file replaced or
removed since it was started, as when \texttt{fsb} is rebuilt while it runs, still
counts), and a process taken from the process-number file must also have the start
time recorded there (\rid{CFG-6}).  Anything else is ignored, so a stale file whose number now
belongs to another process is harmless.  Finding the process, here and in
\rid{CLI-19} and \rid{CLI-20}, needs no other program on Linux, so it works on minimal
systems too; on macOS it uses \code{ps} and \code{lsof}, which are part of the system.
\end{req}

\begin{req}{CLI-19}
\code{--status} reports whether an \texttt{fsb} is running (found as in
\rid{CLI-18}) and, if so, whether in the background or the foreground, its address,
process number, start time and terminal; then exits.
\end{req}

\begin{req}{CLI-20}
If the remembered port (\rid{CFG-5}) is held by another program, \texttt{fsb} does
not start and does not silently choose a different port.  The message names the
port and, when it can be found, the program holding it with its process number,
start time and terminal; if that program is another \texttt{fsb}, it suggests
\code{fsb --stop}.  Otherwise it suggests \code{--port}.
\end{req}

\begin{req}{CLI-21}
\code{--version} prints the version of \texttt{fsb} and the commit it was built from,
on standard output, and exits with status 0 without reading any file or starting
anything.
\end{req}

\subsection{Environment}

\begin{req}{ENV-1}
The home folder is taken from the operating system's notion of the user's home
(the \code{HOME} environment variable), then resolved to its real location, so that
a home folder reached through a symbolic link or an alias is treated as the real
folder.  It determines the default root, the location of the configuration folder,
and the meaning of \code{\~{}} in rules.
\end{req}

\subsection{Configuration files}
\label{sec:config}

\begin{req}{CFG-1}
Configuration is two optional text files in \code{\~{}/.config/fsb/}: \code{ignore}
(hide rules) and \code{deny} (block rules).  Both are global; there are no
per-folder rule files.
\end{req}

\begin{req}{CFG-2}
The files are read once, at startup.  Changes take effect at the next start.
\end{req}

\begin{req}{CFG-3}
If \code{ignore} does not exist, the built-in ignore rules apply (\code{.DS\_Store},
\code{.git/}, \code{node\_modules/}).  If \code{deny} does not exist, the core deny
rules of Section~\ref{sec:core} apply.  If \code{deny} exists it is authoritative:
whatever it does not contain is not enforced, and a core rule that is missing is
reported as in \rid{CLI-11} and \rid{RUL-14}.
\end{req}

\begin{req}{CFG-4}
User preferences (which columns are shown, the width of the preview pane, and the
like) are not configuration files: they are kept in the browser
(Section~\ref{sec:prefs}) and never on disk.  Browsers keep them per address,
including the port, which is why the port itself is remembered (\rid{CFG-5}).
\end{req}

\begin{req}{CFG-5}
\code{\~{}/.config/fsb/lastport} holds the port of the last successful start that
did not use \code{--port}.  It is written after such a start (best effort: a failure
to write it never stops \texttt{fsb}) and read at the next start.  A missing or
malformed file means that nothing is remembered and never stops \texttt{fsb}, unlike
a malformed rule file.
\end{req}

\begin{req}{CFG-6}
While an \texttt{fsb} started with \code{--background} runs,
\code{\~{}/.config/fsb/pid} holds its process number and a record of its start
time that does not depend on the time zone (nor, on Linux, on changes to the clock),
so that \code{--stop} and \code{--status} find it under any \code{TZ}; it is removed when that
\texttt{fsb} stops.  \code{\~{}/.config/fsb/background.log} receives its output
after startup and is replaced at each \code{--background} start.  Both are created
with mode \code{0600}.
\end{req}
